# Анатомия — атлас (веб-приложение)

Атлас человеческого тела с изображениями/схемами и 3D-моделями. Данные можно постоянно добавлять и редактировать через встроенный раздел «Админ» — без правки кода.

## Структура

```
server/   — Node.js + Express API, хранение данных в JSON-файле, загрузка изображений и 3D-моделей
client/   — React (Vite) фронтенд: раздел «Атлас» (просмотр) и «Админ» (добавление/редактирование)
```

## Возможности

- Записи атласа сгруппированы по системам организма (скелетная, мышечная, органы и т.д.) — список систем формируется автоматически из данных.
- Для каждой записи: название, система, описание, изображение/схема **и/или** 3D-модель (`.glb`/`.gltf`).
- **2D-метки**: клик по картинке в админке ставит метку с подписью в нужной точке (в процентах от размера картинки — не зависит от масштаба экрана).
- **3D-метки**: клик по 3D-модели в админке определяет точку на её поверхности (через `positionAndNormalFromPoint`) и добавляет там метку с подписью.
- Если у записи есть и картинка, и 3D-модель — в атласе показывается переключатель 2D/3D.
- Полный CRUD через раздел «Админ»: добавление, редактирование, удаление записей.

## Локальный запуск

### 1. Backend

```bash
cd server
npm install
npm start        # http://localhost:4000
```

Данные хранятся в `server/data/entries.json`, загруженные файлы — в `server/uploads/`.

### 2. Frontend

```bash
cd client
npm install
npm run dev       # http://localhost:5173
```

По умолчанию фронтенд обращается к `http://localhost:4000`. Чтобы изменить адрес API, создайте `client/.env`:

```
VITE_API_URL=http://localhost:4000
```

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/systems` | список систем организма |
| GET | `/api/entries?system=...` | список записей (опционально фильтр по системе) |
| GET | `/api/entries/:id` | одна запись |
| POST | `/api/entries` | создать запись (`multipart/form-data`: `title`, `system`, `description`, `labels` (JSON), `labels3d` (JSON), `image`, `model`) |
| PUT | `/api/entries/:id` | обновить запись |
| DELETE | `/api/entries/:id` | удалить запись |

## Что можно донастроить позже

- Аутентификация для раздела «Админ» (пока без авторизации — только для локального использования).
- Переход с JSON-файла на полноценную БД (SQLite/Postgres), если данных станет много.
- Деплой backend + frontend (например, backend на Render, frontend на статическом хостинге).
