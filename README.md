# Анатомия — атлас (веб-приложение)

Атлас человеческого тела с изображениями/схемами, 3D-моделями и видео, по схеме **Орган → Нозология → Рубрики** (как в справочнике World Medicine). Данные добавляются и редактируются через защищённую логином админку, без правки кода.

## Структура

```
server/   — Node.js + Express API, хранение данных в JSON-файлах, загрузка изображений/3D-моделей/видео, авторизация
client/   — React (Vite) фронтенд: «Атлас» (просмотр), «Админ» (записи), «Карта тела», «Пользователи»
```

## Возможности

- **Схема записи**: Орган (`system`) → Нозология (`title`) → рубрики **Определение / Причины / Симптомы** → **Рекомендуемые препараты компании WM** (список тегов).
- **Профили тела**: каждая запись помечена как `male` / `female` / `child` / `any` (универсальная) — атлас открывается с выбором профиля и фильтрует контент под него.
- **Карта тела**: 2D-изображение и/или 3D-модель целого тела на каждый профиль с кликабельными метками органов — клик сразу открывает список нозологий по этому органу (раздел «Карта тела» в админке).
- **Медиа на запись**: картинка/схема, 3D-модель (`.glb`/`.gltf`) и видео (`.mp4`/`.webm`/`.mov`, в т.ч. рендер 3D-анимации патологии) — с переключателем 2D/3D/Видео.
- **Метки**: клик по картинке или по 3D-модели ставит подписанную метку (на модели — через `positionAndNormalFromPoint`, точка на реальной поверхности).
- **Авторизация**: логин по email/паролю, роли `admin` (полный доступ, включая управление пользователями) и `editor` (работа с контентом). Просмотр атласа открыт всем, редактирование — только вошедшим.

## Локальный запуск

### 1. Backend

```bash
cd server
npm install
cp .env.example .env
# сгенерировать и вписать AUTH_SECRET:
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
npm start        # http://localhost:4000
```

Данные — в `server/data/*.json` (entries, bodymaps; `users.json` не коммитится в git), файлы — в `server/uploads/`.

**Первый администратор** создаётся из командной строки (открытой регистрации нет специально):

```bash
node scripts/create-admin.js admin@example.com пароль admin
```

Второй и последующие аккаунты (например, `editor`) можно добавлять уже через веб-интерфейс — раздел «Пользователи» доступен вошедшему `admin`.

### 2. Frontend

```bash
cd client
npm install
npm run dev       # http://localhost:5173
```

По умолчанию фронтенд обращается к `http://localhost:4000`. Чтобы изменить адрес API, создайте `client/.env`:

```
VITE_API_URL=http://localhost:4000
```

## API

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| GET | `/api/systems?bodyProfile=...` | публично | список органов (опционально по профилю) |
| GET | `/api/entries?system=...&bodyProfile=...` | публично | список записей |
| GET | `/api/entries/:id` | публично | одна запись |
| POST | `/api/entries` | вошедшим | создать запись |
| PUT | `/api/entries/:id` | вошедшим | обновить запись |
| DELETE | `/api/entries/:id` | вошедшим | удалить запись |
| GET / PUT | `/api/bodymaps/:profile` | GET публично, PUT вошедшим | карта тела (male/female/child) |
| POST | `/api/auth/login` | публично | вход, возвращает JWT |
| GET | `/api/auth/me` | вошедшим | текущая сессия |
| GET / POST / DELETE | `/api/users` | только admin | управление пользователями |

Мутирующие запросы принимают токен в заголовке `Authorization: Bearer <token>`.

## Контент

Атлас предзаполнен 8 органами с реальными 3D-моделями:

- **Печень, желудок, поджелудочная железа, жёлчный пузырь, обе почки, мочевой пузырь** — геометрия из [BodyParts3D](http://dbarchive.biosciencedbc.jp/en/bodyparts3d/) (база, на которую опирается сам открытый проект Z-Anatomy — сам Z-Anatomy распространяется только как Blender-шаблон и требует Blender для экспорта; BodyParts3D даёт то же содержимое напрямую в OBJ/STL). Лицензия CC BY-SA 2.1 Japan, конвертация STL → GLB через `trimesh` (Python), без потери геометрии.
- **Мозг** — готовая модель (344 отдельные структуры: кора, базальные ганглии, сосуды виллизиева круга, черепные нервы и др.) из открытого проекта [brainproject](https://github.com/itayinbarr/brainproject), который сам построен на Z-Anatomy/BodyParts3D плюс несколько открытых МРТ-атласов (CIT168, Najdenovska, Neudorfer, HCP1065). Лицензия CC BY-SA 4.0, атрибуция — в описании записи.
- Тексты определений написаны заново на основе общих сведений анатомии/физиологии (не скопированы из чужих источников).

**Ещё не добавлено**: отдельные модели сердца (4 камеры) и лёгких (5 долей) — точные названия частей нашлись в открытом каталоге [anatomed-mcp](https://github.com/pitfa19/anatomed-mcp) (тот же Z-Anatomy → BodyParts3D), но сами файлы (`.glb`) отдаёт Supabase-хостинг, недоступный из окружения, в котором собирался этот проект. Если у вас есть сетевой доступ — можно скачать и добавить их вручную через «Карта тела»/«Админ»:

```
https://uafyfwyyqzunabpuftue.supabase.co/storage/v1/object/public/models/glb/<Part%20name>.glb
```

Нужные имена частей (пробел → `%20`): `Left atrium`, `Left ventricle`, `Right atrium`, `Right ventricle` (сердце); `Superior lobe of right lung`, `Middle lobe of right lung`, `Inferior lobe of right lung`, `Superior lobe of left lung`, `Inferior lobe of left lung` (лёгкие).

### Self-hosted Draco decoder

`model-viewer` по умолчанию тянет декодер для Draco-сжатых моделей (как у brainproject) с CDN `gstatic.com` — в закрытых корпоративных сетях это может не работать. Декодер уже сохранён локально в `client/public/draco/` и подключён в `main.jsx` (`ModelViewerElement.dracoDecoderLocation`), так что интернет для этого не нужен.

## Что можно донастроить позже

- Переход с JSON-файлов на полноценную БД (SQLite/Postgres), если данных станет много или появится параллельное редактирование.
- Лицензированная 3D-платформа (BioDigital Human, Zygote) вместо открытых моделей — вопрос бюджета.
- Деплой backend + frontend (например, backend на Render, frontend на статическом хостинге) и вынос `uploads/` в объектное хранилище.
- Роль `reviewer` и обязательное согласование перед публикацией (черновик/публикация), история версий записей.
